## Attacker path

Mint iETH with ETH, repeatedly call iToken.transfer(self, balance) so the destination write overwrites the source decrement and doubles balance, then burnToEther to redeem ETH.

## Invariant broken

Internal token transfer preserves the sum of source and destination balances.

## Victim impact

iETH market drained on the historical incident; aggregate cross-market loss not authoritatively re-confirmed from PoC code alone.

**Loss check:** iETH loanToken contract underlying ETH balance < pre-attack balance by the duplicated redemption.

## Root cause

_internalTransferFrom updated source then destination from cached pre-call balances, so when source equals destination the second write overwrote the first decrement, doubling the balance.

**Protocol assumption that failed:** Assumed source and destination of an internal transfer are different addresses.
