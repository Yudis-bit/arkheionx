# Arkheionx v5.0.0 — Blind Spot Intelligence

> Local/static, heuristic, additive. No RPC, no live-chain calls, no private
> keys, no exploit automation, no severity, no vulnerability claims. Human review
> is required for every conclusion.

**Release metadata finalized locally; pending founder push, tag, GitHub release,
and site deploy.** The package version is `5.0.0`. The last published tag remains
`v4.0.0`, and the source installers and the GitHub Action still pin to the last
actually-tagged stable release, `v3.1.0`.

## Summary

V5 introduces **Blind Spot Intelligence**: a local/static research layer that
prioritizes high-impact surfaces with weak review evidence, generates
counterfactual research prompts, and packages the result into an AI/human-ready
bug bounty research pack.

V4 maps the protocol. V5 maps where research attention is weakest:

- **V4** answers "how does this protocol work?" — `review-map` shows where value
  enters, moves, and exits, the assumptions that guard each path, and which paths
  have no tests.
- **V5** answers "what are we probably missing?" — it ranks likely blind spots,
  estimates criticality potential (blast radius), and turns assumptions into
  testable counterfactuals.

V5 does not predict vulnerabilities. It identifies assumptions, unknown surfaces,
review-density gaps, and high-impact areas where expensive bugs are more likely
to hide, so a human or an AI agent spends limited review time where it matters.

## New commands

- `arkheionx blind-spots <path>` — rank likely blind-spot candidates with a
  transparent additive score (impact + review-gap + complexity + assumption),
  per-candidate reasons, a suggested counterfactual, a local test direction, the
  evidence needed, and a do-not-claim note. `--json`, `--out`, `--limit`.
- `arkheionx criticality-map <path>` — map criticality potential (heuristic blast
  radius, **not** severity) across surfaces, with a criticality-vs-review-density
  view. `--json`, `--out`.
- `arkheionx counterfactuals <path>` — negate guarding assumptions into testable
  "what if this assumption is false?" research prompts, each with a local test
  direction, the evidence required, and a stop condition. `--json`, `--out`.
- `arkheionx research-pack <path>` — generate a complete local, vendor-agnostic
  research pack (README, review-map summary, blind spots, criticality map,
  counterfactuals, agent brief, hypotheses, evidence log, do-not-claim, case-study
  template, and a JSON manifest). Writes by default. `--json`, `--out`, `--no-write`.

## Compatibility

The stable `review-map` workflow and the v4.1 research-memory commands
(`agent-brief`, `hypothesis-log`, `case-study`) are unchanged. The v5 commands
build directly on `review-map` output and the research-surface engine:

```text
review-map → blind-spots → criticality-map → counterfactuals → research-pack
          → local tests → hypothesis-log → case-study → human decision
```

JSON schemas for all four v5 artifacts live under `schemas/`. A dedicated
`examples/blind-spot-fixture` exercises every detector category in one repo.

## Known limitations

- Heuristic and static. Blind spot detection is not perfect: it can miss surfaces
  and can rank a well-reviewed surface highly.
- No bug prediction. No severity. Criticality potential is blast-radius potential,
  not a severity and not a probability.
- No RPC, no live-chain calls, no exploit automation, no auto-submit.
- Real-protocol validation is still required; a finding is only ever confirmed by
  a human with independent local proof.

## Safety boundaries

Local/static repository analysis only. No RPC, no live-chain mutation, no private
keys or secrets, no exploit automation, no transaction broadcasting, no
auto-submit. Not an audit, certification, or replacement for manual review. Human
review is required.
