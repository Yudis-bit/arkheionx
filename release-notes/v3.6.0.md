## 1. Summary

v3.6.0 introduces the **Review Package Workspace**: a local-first package layer
that turns the review artifacts Arkheionx already writes — the review-map,
value paths, assumptions, test gaps, proof plan, proof/trace receipts, evidence
packages, report drafts, evidence-links, and the optional Protocol Intelligence
Model — into one structured, self-describing pre-audit package for human review.
The new `arkheionx review-package` command collects existing local artifacts,
records their checksums in a manifest, validates the package, generates a
reviewer `README.md` and `limitations.md`, optionally includes a protocol-model
sidecar with exact-match cross-reference checks, and can write a deterministic
local ZIP archive. It assembles existing local context only: it runs no new
analysis, raises no evidence level, keeps `manual_review_required` true and
`ready_for_submission` false, and is never published by Arkheionx.

## 3. Review Package Workflow

```sh
arkheionx review-package <repo> --no-write --json
arkheionx review-package <repo> --json
arkheionx review-package <repo> --export zip --json
```

- The dry run (`--no-write`) builds the manifest, checksums, validation, and the
  in-memory protocol model but writes nothing — no package folder and no archive.
- The build writes the local package folder under
  `.arkheionx/out/review-package/`.
- The export writes a deterministic local ZIP under `review-package/exports/`.
- The protocol-model sidecar is included when buildable from review-map output;
  `--no-protocol-model` skips it and `--include-protocol-model` makes the intent
  explicit.
- Cross-reference warnings are guidance and require review; they never block a
  build and never invent links.

## 4. Package Output Layout

```text
.arkheionx/out/review-package/
  manifest.json
  validation.json
  README.md
  limitations.md
  artifacts/
    review-map/...
    proofs/ traces/ evidence/ reports/ ...
    intelligence/protocol-model.json   # when buildable
  checksums/SHA256SUMS
  exports/
    arkheionx-review-package-<id>.zip  # only with --export zip
```

All recorded paths in the generated package metadata are repo-relative or
package-relative; the build writes no absolute path into `manifest.json`,
`validation.json`, `README.md`, `limitations.md`, or `checksums/SHA256SUMS`.

## 5. Validation and Checksums

The validator is local, static, and read-only. It produces `validation.json`
with:

- Manifest shape checks (`manifest_version`, `package_id`, list fields).
- Required-artifact checks (a missing required artifact yields
  `PACKAGE_PARTIAL`, a warning-level state, not an error).
- Path-safety checks (absolute paths, backslashes, traversal, and home-directory
  leaks are flagged).
- Checksum checks (recorded sha256 vs the file on disk).
- A secret-pattern scan that reports only a pattern-class name (for example
  private-key-like or rpc-url-like) and a relative path, never a secret value.
- Safety-boundary checks (the manifest must declare the safety flags true,
  `manual_review_required` true, and `ready_for_submission` false; emitting a
  human-reviewed status is a failure).

Across every result, `manual_review_required` stays true and
`ready_for_submission` stays false; the package is review-oriented and is never
marked ready for submission.

## 6. Deterministic Export

`--export zip` writes a reproducible local archive:

- A stable `arkheionx-review-package/` archive root.
- Relative-only entries (no absolute, backslash, or traversal entries).
- Fixed entry metadata where possible (fixed timestamp and permission bits).
- Lexicographically sorted entries.
- Excludes the `exports/` directory and the archive itself.
- Excludes caches, VCS metadata, and other unsafe files
  (`__pycache__`, `.git`, `.DS_Store`, `.pyc`).
- Checksum stability verified by Agent 9: a second export with unchanged inputs
  produced an identical `export_checksum_sha256` and entry list.

The archive is local only; Arkheionx never transmits, uploads, or publishes it.

## 7. Protocol Intelligence Integration

- The package can include an `artifacts/intelligence/protocol-model.json`
  sidecar built additively from existing review-map output, with the absolute
  repo path scrubbed.
- Cross-reference validation resolves the IDs that artifacts reference against
  the model by exact ID match.
- Resolution also accepts an explicit alias only.
- There is no fuzzy matching.
- There is no substring matching.
- Unresolved references produce warnings, never errors.
- No invented or fabricated links are ever added; a missing protocol model is a
  warning, not an error.

## 8. Safety Boundaries

Arkheionx remains local/static review guidance only:

- local/static only
- no RPC
- no private keys
- no seed phrases
- no live-chain calls
- no transaction broadcasting
- no exploit automation
- no auto-submit
- no automatic `HUMAN_REVIEWED`
- no confirmed vulnerabilities
- no final severity
- no audit-passed claim
- no bounty eligibility
- manual review required
- `ready_for_submission` false

The review package organizes local review context only. It does not turn
heuristic signals, proof receipts, evidence packages, reports, or links into
vulnerability confirmation, exploitability proof, final severity, or submission
readiness. It is not a formal audit and not a replacement for manual review.

## 11. Known Limitations

- Not a formal audit.
- Not a vulnerability confirmation tool.
- No final severity.
- No bounty eligibility.
- No automatic submission and no auto-submit.
- Manual review is required before any use or sharing.
- v3.6.0 is finalized locally (metadata, dating, and the local `v3.6.0` tag are
  set); it is not pushed or published, and there is no GitHub Release.
- The Foundry-coverage / local-validation lane is deferred to a later milestone
  (sequenced around v3.8.0).
- Copied legacy artifacts may retain pre-existing local path fields (for example
  a review-map `repo_path`); the generated v3.6 package metadata itself avoids
  absolute-path leakage, and the protocol-model sidecar scrubs the absolute repo
  path.
