# Arkheionx v2.10.0 — Pre-v3 Public Readiness & Stability Hardening

Arkheionx v2.10.0 is the final v2 hardening milestone before the v3.0 public
stable cut. It adds no new product features. Instead it documents and locks the
public command surface, states a stability contract, defines a v3 readiness
checklist, polishes output and error messages, and adds a release-readiness
gate. The v2.9.0 workflow and bundled demos are unchanged.

> Release date: 2026-05-31. Package version `2.10.0`. The `STABLE_RELEASE`
> pointer remains `v2.9.0` until this release is published, then moves to
> `v2.10.0` in post-release cleanup. Not published to PyPI; no Homebrew,
> standalone binary, or domain installer. Not a formal audit; no bounty or
> severity guarantee.

## Public command surface inventory

`docs/PUBLIC_SURFACE.md` lists all 18 CLI commands and the three shell scripts
(`install.sh`, `uninstall.sh`, `arkup`) with purpose, output mode, artifact
behavior, and a stability label (stable / stable-additive / internal-legacy). A
contract test (`tests/test_public_surface_contract.py`) fails if a command in
`arkheionx --help` is missing from the doc, guarding against drift.

## Stability contract

`docs/STABILITY_CONTRACT.md` states what stays stable into v3.0: public command
names, additive JSON/schema changes, plain JSON and artifacts, the install/
update lifecycle, and never-weakened safety boundaries. Human-readable output
may be polished; internal Python modules are not a stable import API.

## v3 readiness checklist

`docs/V3_READINESS.md` is an honest, actionable checklist across command
surface, install/update, demos, package data, output, evidence model, artifact
validation, docs, safety, and release process — plus what v3.0 will not claim.

## Output consistency and error-message polish

Human-facing commands share the `ARKHEIONX <COMMAND>` / `Status:` / `Next`
shape with restrained, TTY-gated color (`ARKHEIONX_COLOR=always|never|auto`,
honoring `NO_COLOR` and `CI`). JSON output and artifact files stay plain.
Common error messages (unknown demo id, non-empty copy destination, missing
target, missing Foundry project) state what happened and the next command.

## Release readiness gate

`scripts/check_release_readiness.py --check` aggregates version consistency,
docs links, and safety wording with readiness-specific checks: surface/contract/
readiness docs exist, public commands are documented, README stable line and
visuals are present, fixtures exist, demo ids are documented, release notes and
changelog sections exist, and no forbidden distribution claims appear. It runs
in `make validate`.

## End-to-end workflow tests

`tests/test_public_workflow.py` copies each demo to a temp dir and runs
open → hunt → evidence-status → validate-artifacts with no network, no secrets,
and no RPC, asserting headings, exit behavior, and that artifacts are written
only under the expected directory with no ANSI. Foundry-dependent prove/trace
is exercised only when `forge` is available, otherwise skipped with a reason.

## Safety boundaries

- Local-only; no RPC by default; no private keys; no secrets; no mainnet; no
  live-chain instructions; no real deployed addresses; no bounty framing; no
  severity guarantee; no auto-submission; no automated exploitation.
- Not an audit, certification, or replacement for manual review.
- No PyPI, Homebrew, standalone binary, or domain installer.

## Validation

- `python3 -m unittest discover -s tests -p "test_*.py"` — full suite.
- `make validate` — docs links, version consistency, safety wording, readiness gate.
- `sh -n install.sh uninstall.sh arkup`; color/JSON/demo-copy smoke.

## Known limitations

- Heuristic-first; Foundry optional; local-only; not a formal audit.
- Three bundled toy demos; no real protocol targets.
- Not published to PyPI; no Homebrew, standalone binary, or domain installer.
