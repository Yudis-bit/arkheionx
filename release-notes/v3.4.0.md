## 1. Summary

v3.4.0 deepens Arkheionx from focused review-map commands into a connected
proof/evidence/report readiness workflow. This local final release ties local
proof and trace artifacts to deterministic evidence packages, draft reports,
focused evidence links, and enriched review-map artifacts while preserving the
local/static safety boundary and manual-review requirement.

## 2. What Changed Since v3.3.0

- Trace-bounded evidence readiness.
- `evidence --from-proof` with a missing adjacent trace cannot promote to
  `EVIDENCE_READY`.
- `prove --json --no-artifacts` emits pure JSON and writes no proof artifacts.
- Proof and trace artifacts carry receipt/linkage fields.
- Evidence packages include deterministic `evidence_package_id` values.
- Evidence packages include additive manifests with source records and checks.
- `validate-artifacts` catches stronger evidence package inconsistencies.
- Report drafts include `evidence_context`.
- Report drafts include `receipt_references`.
- Report drafts include `report_readiness`.
- Report drafts include bounded `claim_references`.
- `evidence-links` backfills proof, trace, evidence, and report receipt context
  from existing local artifacts.
- `review-map` writes enriched evidence-link artifacts when local proof,
  evidence, and report artifacts exist.
- Agent 6 QA gate passed with `READY_FOR_V3_4_RELEASE_PREP`.
- Agent 7 release prep passed with `READY_FOR_V3_4_FINAL_LOCAL_RELEASE`.

## 3. Workflow

The v3.4 workflow is:

```text
proof -> trace -> evidence package -> report draft -> evidence-links -> review-map
```

Example local commands:

```sh
arkheionx prove . --target <Contract.function> --run
arkheionx evidence . --from-proof .arkheionx/out/proof/<slug>/proof.json
arkheionx report . --from-evidence .arkheionx/out/evidence/<slug>/evidence.json
arkheionx evidence-links .
arkheionx review-map .
```

These commands prepare local review artifacts only. They do not publish,
submit, or confirm a vulnerability.

## 4. Evidence Readiness Contract

- Execution proof plus real linked trace -> `EVIDENCE_READY`
- Execution proof without linked trace -> `EXECUTION_CONFIRMED`
- Compiler proof -> `COMPILER_CONFIRMED`
- Scaffold/no proof -> `HEURISTIC`

Missing trace sources are not faked. When no trace exists,
`source_artifacts.trace_json` remains empty and the proof source path remains the
actual proof artifact path used as input.

## 5. Evidence Package

Evidence packages now include:

- `evidence_package_id`
- `manifest`
- manifest source records for proof artifacts
- manifest source records for trace artifacts only when a real trace exists
- recorded proof and trace source paths
- readiness checks such as `trace_linked` and
  `trace_required_for_evidence_ready`
- `human_review_required`

`validate-artifacts` now checks for contradictions such as `EVIDENCE_READY`
without a linked trace, stale manifest source existence flags, manifest/source
path mismatches, and false `trace_linked` checks on evidence-ready packages.

## 6. Report Draft

Report drafts now include:

- `evidence_context`
- `receipt_references`
- `report_readiness`
- `claim_references`

Reports remain draft-only. Manual review is required, `ready_for_submission`
stays false, and Arkheionx does not emit `HUMAN_REVIEWED` automatically. Claim
references stay bounded review context and do not assign final severity or
confirm vulnerabilities.

## 7. Review-Map and Evidence-Links

`evidence-links` can surface existing local proof, trace, evidence, and report
artifacts. When those artifacts exist, evidence-link output can include:

- `evidence_package_id`
- `proof_receipt_id`
- `trace_receipt_id`
- evidence package paths
- draft report paths
- manual-review context

`evidence-links` remains read-only. It does not create evidence, execute proofs,
promote evidence levels, create reports, or confirm vulnerabilities. `review-map`
writes enriched `review-map/evidence-links.json` from the same local artifact
context.

## 8. Safety Boundaries

Arkheionx remains local/static review guidance only:

- no RPC
- no private keys
- no live-chain calls
- no transaction broadcasting
- no exploit automation
- no auto-submit
- no confirmed vulnerabilities
- no final severity
- no bounty eligibility
- human review required
