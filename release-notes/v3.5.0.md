## 1. Summary

v3.5.0 introduces the internal **Protocol Intelligence Model**: a stable
deterministic ID layer and a set of normalized dataclasses that connect, through
shared IDs, the entities Arkheionx already produces — contracts, functions,
value paths, assumptions, test gaps, proof suggestions, proof receipts, trace
receipts, evidence packages, report drafts, evidence-links, and review-map
targets. It is internal infrastructure built additively on top of the existing
`analyze()` and review-map outputs: it adds no new CLI command, changes no
public artifact shape or schema, preserves every v3.4 behavior, and keeps the
local/static safety boundary unchanged. It organizes local review context only —
never confirmed vulnerabilities, final severity, or submission readiness.

## 2. What Changed Since v3.4.0

- Internal stable ID utilities (`arkheionx/intelligence/ids.py`): deterministic
  ID builders derived only from normalized structural inputs.
- `ProtocolModel` dataclasses (`arkheionx/intelligence/model.py`): one normalized
  local review model with per-entity nodes.
- Deterministic protocol / contract / function / value-path / assumption /
  test-gap / proof-suggestion / proof-receipt / trace-receipt / evidence-package
  / report / evidence-link IDs.
- `ProtocolModel` builder (`arkheionx/intelligence/build.py`) from `analyze()`
  and review-map outputs (`build_protocol_model_from_analysis`,
  `build_protocol_model_from_review_map`), with alias-based function resolution
  (`resolve_function_id_by_alias`, `index_functions_by_alias`).
- Additive review-map intelligence IDs: review-map internals carry shared
  `contract_id` / `function_id` identity while every existing review-map key and
  artifact remains present.
- Reasoning links (`arkheionx/intelligence/linking.py`):
  value paths -> assumptions -> test gaps -> proof suggestions.
- Artifact links:
  proof -> trace -> evidence package -> report draft -> evidence-links.
- Compatibility hardening for old v3.4 artifacts that have no intelligence
  fields.
- Target-resolution / no-overlink tests (ambiguous display names resolve to no
  link rather than a wrong link).
- Public regression tests confirming the v3.4 public surface is unchanged.
- Agent 8 QA gate passed with decision `READY_FOR_V3_5_RELEASE_PREP`.

## 3. Workflow Context

The Protocol Intelligence Model organizes existing review context into one
internal model:

```text
review-map / analysis
-> ProtocolModel
-> value paths
-> assumptions
-> test gaps
-> proof suggestions
-> proof receipts
-> trace receipts
-> evidence packages
-> report drafts
-> evidence-links
```

The v3.4 command workflow is preserved exactly and remains the user-facing path:

```text
proof -> trace -> evidence package -> report draft -> evidence-links -> review-map
```

The model is built from existing outputs; it does not replace `review-map.json`
or change any command's behavior.

## 4. Stable ID Model

`arkheionx/intelligence/ids.py` provides deterministic builders for:

- `protocol_id`
- `contract_id`
- `function_id`
- `value_path_id`
- `assumption_id`
- `test_gap_id`
- `proof_suggestion_id`
- `proof_receipt_id`
- `trace_receipt_id`
- `evidence_package_id`
- `report_id`
- `evidence_link_id`

Properties:

- Deterministic — every ID derives from a SHA-256 digest over a canonical,
  key-sorted JSON seed of normalized structural inputs.
- No random values.
- No timestamps.
- No process-specific `hash()`.
- Same source target produces the same ID across runs and processes.
- Each ID keeps a human-readable prefix (e.g. `function:`, `value-path:`) for
  debugging only.
- Old IDs and display names (e.g. `stable_id` / `qualified_id` / `target_id`,
  `vp-` / `asm-` / `gap-` / `proof-` / `ev-` slugs, `review_map_target`) remain
  as aliases, never as primary joins.
- Public compatibility preserved: existing artifact IDs are unchanged.

## 5. ProtocolModel Entities

`arkheionx/intelligence/model.py` defines the `ProtocolModel` container and these
nodes (every node carries an `aliases` map and a `metadata` map):

- `ProtocolModel`
- `ContractNode`
- `FunctionNode`
- `ValuePathNode`
- `AssumptionNode`
- `TestGapNode`
- `ProofSuggestionNode`
- `ProofReceiptNode`
- `TraceReceiptNode`
- `EvidencePackageNode`
- `ReportDraftNode`
- `EvidenceLinkNode`

Serialization is via `to_dict` / `ProtocolModel.to_dict()` (plain, JSON-ready,
deterministic for stable inputs). `confidence` reflects heuristic model
certainty and `evidence_level` reflects proof strength; the two are kept
separate and never merged. The default `evidence_level` is `HEURISTIC` and is
never auto-promoted, and `ReportDraftNode.review_status` defaults to
`NEEDS_HUMAN_REVIEW`.

## 8. Safety Boundaries

Arkheionx remains local/static review guidance only:

- local/static analysis only
- no RPC
- no private keys
- no live-chain calls
- no transaction broadcasting
- no exploit automation
- no auto-submit
- no automatic `HUMAN_REVIEWED`
- no confirmed vulnerabilities
- no final severity
- no bounty eligibility
- manual review required

The Protocol Intelligence Model organizes local review context only. It does not
turn heuristic signals, proof receipts, evidence packages, reports, or links into
vulnerability confirmation, exploitability proof, final severity, or submission
readiness. It is not an audit and not a replacement for manual review.
