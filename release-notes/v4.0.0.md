# Arkheionx v4.0.0 — Stable local review-map workflow

**Release candidate prepared locally; pending founder push/tag/GitHub release/site
deploy.** This finalizes the package version at `4.0.0`. The `v4.0.0` git tag and
GitHub Release are founder actions; the last actually-tagged stable release
remains `v3.1.0` until that tag is cut, which is what the source installers and
the GitHub Action pin to. No PyPI publication, no safety guarantee, and no
vulnerability confirmation; `manual_review_required` stays true.

## What v4.0.0 stabilizes

v4.0.0 makes the local **review-map** workflow the stable, supported public
surface: `review-map` plus the focused views `value-paths`, `assumptions`,
`test-gap-map`, and `proof-plan`, with `version` and `doctor` for orientation.

## What changed since v3.9.0

- Package version finalized at `4.0.0`; current milestone `v4.0.0`, next `v4.1.0`.
- One coherent product surface across README, `docs/`, the website, CLI, demo,
  and release notes, all anchored on the review-map workflow.
- The Test Gap Map surfaces honest `Source: <file>:<line>` evidence.
- Website matured with how-it-works, bug-bounty, pre-audit, and V4 release pages.

```sh

```

## Safety boundaries

Local and static only. No RPC, no live-chain calls, no exploit automation, no
private-key handling. Arkheionx does not confirm vulnerabilities, assign final
severity, prove protocol safety, or replace an audit. Human review is required.

## Known limitations

- Static heuristics, not execution.
- Cross-contract value flow is surfaced as per-contract paths; end-to-end tracing
  is roadmap work.
- `evidence_links` is empty until local proof/trace artifacts are generated.
- Depth is shown on fixtures; real-protocol validation is planned.
