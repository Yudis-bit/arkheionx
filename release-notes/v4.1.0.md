## What v4.1.0 adds

v4.1.0 extends the stable v4.0 **review-map** workflow into a local, static
**research memory** layer for AI-assisted bug bounty and pre-audit review:

> Arkheionx gives the map. The agent grinds the tests. The research memory keeps
> the evidence. The human makes the final call.

The stable workflow is unchanged:

```text
repo → review-map → value paths → assumptions → test gaps → proof direction → human review
```

v4.1 adds, on top of `review-map`:

```text
review-map → agent brief → hypotheses → Foundry/manual tests → rejected/confirmed evidence → case study → human decision
```

## New commands

- `arkheionx agent-brief <path>` — an AI-agent-ready review brief built from the
  review map: repository summary, coverage weakness ranking, value movement, test
  gaps, authorization surfaces, periphery/core surfaces, behavior-mismatch
  surfaces, open hypotheses, and a do-not-claim boundary.
- `arkheionx hypothesis-log <path>` — a structured hypothesis log and
  rejected-finding memory. Every hypothesis starts `open` with empty fields for
  test command, result, rejection reason, confirmation notes, and human decision.
- `arkheionx case-study <path>` — a sanitized research-session report; `--from`
  incorporates a hypothesis log's statuses. It makes no vulnerability claim
  unless a finding is independently confirmed.

All three emit human Markdown and `--json`, and write artifacts under
`.arkheionx/research/` (unless `--no-write`).

## Research surface engine

Built additively on the review map (`arkheionx/research/`):

- **Coverage weakness ranking** — high-value + weak coverage = inspect first
  (heuristic; review order, not severity).
- **Authorization-surface detection** — signature, EIP-712 domain, chain id,
  nonce, deadline, Merkle proof, ratifier/gate, role, and ownable signals.
- **Periphery-to-core flow mapping** — routers/bundles/multicall, cross-contract
  calls, try/catch, low-level calls, and loops over operations.
- **Behavior-mismatch heuristics** — documented skip/continue/best-effort/partial
  behavior vs an earlier revert (a "potential behavior-mismatch review surface").

## Safety boundaries

Local and static only. No RPC, no live-chain calls, no exploit automation, no
private-key handling, no auto-submit. Hypotheses are review prompts, not
vulnerabilities; rejected hypotheses are useful evidence. Arkheionx does not
confirm vulnerabilities, assign final severity, prove protocol safety, or replace
an audit. Human review is required.

## Known limitations

- Static heuristics, not execution; all surfaces and hypotheses are review
  prompts.
- Detection is exercised on local fixtures; real-protocol validation is planned
  for a later milestone.
- `confirmed` is never set by Arkheionx; only a human sets it, and only with
  independent local proof.

See `docs/V4_1_RESEARCH_WORKFLOW.md` and `docs/RESEARCH_MEMORY_MODEL.md`.
