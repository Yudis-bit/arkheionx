# Arkheionx v2.4.0 — Evidence Workflow Hardening

Arkheionx v2.4.0 makes the local evidence workflow easier to inspect, validate,
and trust. The loop already existed in v2.3.0; v2.4.0 makes it solid.

> Release date: 2026-05-31. Package version `2.4.0`. Not published to PyPI.
> Not a formal audit; no bounty or severity guarantee.

## Summary

When a researcher runs Arkheionx on a real repo, they can now see what evidence
exists, what is missing, what is safe to report, and exactly what command to run
next — across the whole hunt → prove → trace → evidence → report loop.

## Highlights

- `arkheionx evidence-status` — what proof/evidence/report artifacts exist, per target.
- `arkheionx validate-artifacts` — local validation of generated artifacts.
- Artifact index (`.arkheionx/out/artifacts-index.json`) for fast, deterministic status.
- Report review statuses and hardened report drafts (What Is Proven / Not Proven / Required Human Checks).
- Consistent next-command chain across every command.

## New Commands

- `arkheionx evidence-status <repo>` (`--target`, `--json`)
- `arkheionx validate-artifacts <repo>` (`--json`)

## Artifact Validation

Checks required fields, legal evidence-level transitions (e.g. EXECUTION_CONFIRMED
must have an executed test; EVIDENCE_READY must have a trace artifact), referenced
paths, and that report drafts keep a safety notice with no disallowed phrasing.
Exit `0` valid, `1` issues found, `2` command failure.

## Report Readiness

Each target is classified NO_PROOF → PROOF_ONLY → TRACE_READY → EVIDENCE_READY →
REPORT_DRAFTED. Drafted reports are labelled NEEDS_HUMAN_REVIEW and never claim a
final severity.

## Artifact Index

`prove`/`trace`/`evidence`/`report` refresh `.arkheionx/out/artifacts-index.json`.
`evidence-status` rebuilds it by scanning when needed. Runtime artifacts are
gitignored.

## Safety Boundaries

- Local analysis only; no RPC by default; no live-chain mutation.
- No auto-submit; no final severity; no live-chain reproduction steps.
- Not a formal audit; no severity guarantee.

## Validation

- `python3 -m unittest discover -s tests -p "test_*.py"` — full suite passing.
- `make validate` — passing.
- CLI smoke — passing (empty repo, malformed artifacts, and a full Foundry
  fixture loop through evidence-status + validate-artifacts).

## Known Limitations

- Status and validation are local inspection tools, not submission or grading.
- Validation is internal/deterministic (no third-party JSON-schema runtime).
- Not published to PyPI in this release.
