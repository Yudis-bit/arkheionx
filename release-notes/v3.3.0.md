## 1. Summary

v3.3.0 is the Focused Review Commands release. It turns key `review-map`
sub-outputs into focused CLI commands so developers can inspect specific
pre-audit readiness views directly instead of opening the full review-map
artifact bundle.

The release story is:

- v3.1.0 introduced `arkheionx review-map`.
- v3.2.0 hardened review-map output and local artifacts.
- v3.3.0 promotes stable review-map artifacts into first-class focused commands.

## 2. What changed since v3.2.0

- Added five focused review-map commands.
- Added cross-command integration coverage for shared options, JSON purity,
  `--no-write`, target filtering, existing-artifact reads, and execution
  artifact boundaries.
- Preserved the existing review-map artifact model and `review-map --json`
  compatibility.
- Kept the local/static safety boundary unchanged.

## 3. Focused commands

```sh
arkheionx test-gap-map <repo>
arkheionx value-paths <repo>
arkheionx assumptions <repo>
arkheionx proof-plan <repo>
arkheionx evidence-links <repo>
```

Command purpose:

- `test-gap-map` shows what tests or local proofs to prioritize first.
- `value-paths` shows where value enters, moves, and can exit.
- `assumptions` shows protective review prompts tied to value paths.
- `proof-plan` shows suggested local proof outlines.
- `evidence-links` shows links to existing local proof, trace, evidence, or
  report artifacts.

## 4. Shared command behavior

All five focused commands support:

- `--json`
- `--no-write`
- `--out`
- `--target`
- `--top`
- `--include-low-confidence`

Focused commands read existing `.arkheionx/out/review-map/` artifacts when
present. When a focused artifact is missing, or when target/confidence options
require a fresh projection, the command derives the payload locally through the
existing review-map builder.

`--no-write` builds in memory and writes nothing. `--out <dir>` points to the
explicit review-map output directory used for reading or writing review-map
artifacts.

## 5. JSON and artifact compatibility

JSON mode emits the same payload shape as the matching review-map artifact:

- `test-gap-map.json`
- `value-paths.json`
- `assumptions.json`
- `proof-plan.json`
- `evidence-links.json`

The focused commands do not wrap those payloads in a new envelope. Existing
review-map artifact filenames remain unchanged, and `review-map --json`
compatibility is preserved.

## 6. Safety boundaries

Arkheionx remains local/static review guidance only:

- no RPC
- no private keys or seed phrases
- no live-chain calls
- no transaction broadcasting
- no exploit automation
- no auto-submit
- no confirmed vulnerability claims
- no final severity claims
- human review required

`proof-plan` is planning-only. It does not execute proofs and has no `--run`.

`evidence-links` is read-only over existing linked local artifacts. It does not
create evidence, modify evidence records, or promote evidence levels.

## 7. Known limitations

- Static/heuristic signals can be incomplete or false positive.
- Target filtering follows existing review-map builder semantics.
- `evidence-links` depends on existing local artifacts under `.arkheionx/out/`.
- `proof-plan` does not execute proofs.
- Focused commands do not replace manual review or a formal audit.
