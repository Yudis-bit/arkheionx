# Arkheionx v2.9.0 — Multi-Fixture Demo Expansion & Public Workflow Hardening

Arkheionx v2.9.0 broadens the bundled demo set so the workbench demonstrates
multiple DeFi surfaces — staking, AMM, and lending — while staying local-only
and safe. The v2.8.0 package-data foundation and the core evidence workflow are
unchanged.

> Release date: 2026-05-31. Package version `2.9.0`. The `STABLE_RELEASE`
> pointer remains `v2.8.0` until this release is published, then moves to
> `v2.9.0` in post-release cleanup. Not published to PyPI. Not a formal audit;
> no bounty or severity guarantee.

## Summary

`arkheionx demo --list` now offers three toy fixtures so a new developer can
explore different protocol shapes:

```text
oracle-staking  [staking]   Target: OracleRewardFixture.stake
amm-swap        [amm]       Target: AMMSwapFixture.swapAForB
lending-vault   [lending]   Target: LendingVaultFixture.borrow
```

## Highlights

- New bundled fixtures: `amm-swap` and `lending-vault`.
- Demo registry metadata: `category`, `risk_theme`, `safety_label`.
- `demo --list`/`--show` surface category and risk theme.
- Removed the unused dummy `ark-shot.sh`.

## What changed since v2.8.0

- Added `amm-swap` and `lending-vault` package-data fixtures.
- Expanded the `Demo` model and registry; hardened demo output for multiple demos.
- Refreshed demo/onboarding/package-data docs with a selection table.
- Version metadata finalized to `2.9.0`.

## New demo fixtures

- `amm-swap` — toy constant-product AMM (`AMMSwapFixture`): swap, reserves,
  `getAmountOut`, liquidity add/remove, slippage and owner-only fee surfaces.
- `lending-vault` — toy lending market (`LendingVaultFixture`): deposit/borrow/
  repay/withdraw, collateral/debt accounting, an owner-set local price, and a
  health-factor / liquidation review surface.

Both are small, local-only toy fixtures — not production protocols, not real
vulnerabilities, not bounty submissions, and not severity claims.

## Demo registry metadata

Each demo now carries `category` (staking/amm/lending), `risk_theme`
(oracle/rewards, swap/reserves, collateral/debt), and a `safety_label`. The CLI
shows the category in `--list` and the category + risk theme in `--show`.

## Package-data multi-fixture support

All fixtures live under `arkheionx/demo/fixtures/<id>/` and are bundled via
`[tool.setuptools.package-data]` (`**/*.md`, `**/*.toml`, `**/*.sol`). Generated
artifacts are never bundled. `arkheionx demo --copy <id> <dest>` works from an
installed package for every demo. See `docs/PACKAGE_DATA.md`.

## First-use workflow improvements

`docs/DEMO_WORKFLOW.md` adds a demo selection table; onboarding/try-in-5-minutes
docs explain how to pick a surface. Pick a demo, copy it, then run
open → hunt → (optional Foundry) prove/trace/evidence/report.

## Safety boundaries

- Local-only; no RPC; no private keys; no secrets; no mainnet; no live-chain
  instructions; no real deployed addresses; no bounty framing; no severity.
- No PyPI, Homebrew, standalone binary, or domain installer.

## Validation

- `python3 -m unittest discover -s tests -p "test_*.py"` — full suite.
- `make validate` — docs links, version consistency, safety wording.
- Per-demo `demo --list/--show/--commands/--copy`, copy from a non-repo cwd,
  package-resource smoke, and a non-editable venv install smoke.

## Known limitations

- Three bundled toy demos; no real protocol targets.
- No PyPI/Homebrew/binary/domain installer.
- Demos run in `HEURISTIC` mode without Foundry.

## Upgrade

```sh
git pull
sh arkup --update          # or: pip install -e .
arkheionx demo --list
arkheionx demo --copy amm-swap ./demo-amm
```
