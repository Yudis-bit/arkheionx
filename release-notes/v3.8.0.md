## 2. Summary

v3.8.0 is **Protocol Intelligence Core Machine Leverage**: an internal, additive
engine layer (`arkheionx/intelligence/`) that connects the structure Arkheionx
already extracts from a local repository into one deterministic, reviewable
surface — function roles, value paths, assumptions, test gaps, a protocol graph,
and local-validation coverage correlation. Higher layers can carry this surface
as optional supporting context: evidence packages and report drafts can attach an
optional protocol-graph context, and the review package can include optional
protocol-graph artifacts when they already exist on disk.

It is "machine leverage" in a deliberately narrow sense: it organizes and
connects review context deterministically so a person can review faster. It does
not decide anything. The core is built additively from the structure Arkheionx
already extracts (including the stable `arkheionx review-map` analysis output);
it adds no new public CLI command, no graph CLI, and no protocol-graph writer,
and the milestone prioritizes core review depth over UI or command-surface
expansion. Every record uses exact-only linking and deterministic IDs, keeps
`manual_review_required` true and `ready_for_submission` false, and never emits a
`HUMAN_REVIEWED` status.

## 4. Function Role Taxonomy

The role engine assigns controlled, descriptive review roles to a Solidity
function from its name and signature using boundary-aware token matching — never
substring or fuzzy matching. The controlled roles are `INFLOW`, `OUTFLOW`,
`ACCOUNTING_MUTATION`, `EXTERNAL_CALL`, `ORACLE_CONSUMER`, `ORACLE_SETTER`,
`ADMIN_PARAM`, `ACCESS_CONTROL`, `PAUSE_EMERGENCY`, `UPGRADE_PROXY`,
`DELEGATECALL`, `BORROW_REPAY`, `LIQUIDATION`, `SWAP`, `MINT_BURN`,
`CLAIM_REWARD`, `BRIDGE`, and `VIEW_PURE`, plus `UNCLASSIFIED` (which never
implies safety). A stable role priority orders the output for review; it is never
a severity. Role IDs are deterministic, and a classification's `confidence`
reports a structural classification only, never security confidence.

## 5. Value Path Graph Model

The value-path engine maps roles into controlled value-path kinds with ordered
segments: `VALUE_INFLOW`, `VALUE_OUTFLOW`, `ACCOUNTING_MUTATION_PATH`,
`EXTERNAL_CALL_PATH`, `ORACLE_DEPENDENT_PATH`, `AUTHORITY_PATH`, `EMERGENCY_PATH`,
`UPGRADE_PATH`, `LIQUIDATION_PATH`, `SWAP_PATH`, `BRIDGE_PATH`, `REWARD_PATH`,
`VIEW_ONLY_PATH`, and `UNCLASSIFIED_PATH`. The mapping is exact and non-inventive:
assets, oracle sources, external targets, and state variables stay empty unless
explicit data is supplied, and an ambiguous mapping records a warning rather than
guessing.

## 6. Assumption Engine

The assumption engine derives the protective assumptions each value path relies
on and records a support level (`ASSUMPTION_OBSERVED`, `ASSUMPTION_CLASSIFIED`,
`ASSUMPTION_LINKED`, `ASSUMPTION_TESTED`, `ASSUMPTION_TRACE_BOUND`, or
`ASSUMPTION_NEEDS_HUMAN_REVIEW`). A higher support level means more local context
exists, never that the assumption is proven safe.

## 7. Test Gap Engine

The test-gap engine records what is unproven today and how to review it first,
with a gap status (`TEST_GAP_OPEN`, `TEST_GAP_PARTIALLY_COVERED`,
`TEST_GAP_LOCALLY_TESTED`, `TEST_GAP_TRACE_BOUND`, `TEST_GAP_NEEDS_HUMAN_REVIEW`,
or `TEST_GAP_UNCLASSIFIED`) and a review priority (`GAP_PRIORITY_UNKNOWN` through
`GAP_PRIORITY_CRITICAL_REVIEW`). Priority is review order, never severity. A
`LOCALLY_TESTED` or `TRACE_BOUND` gap is supported by context only; it is not a
resolved or safe verdict.

## 8. Protocol Graph Builder

The graph builder composes roles, value paths and segments, assumptions, and test
gaps into one deterministic graph of nodes and edges, plus a deterministic
consistency-check layer. Edges link concepts by exact ID or explicit alias only;
a missing target is an unresolved-reference warning, never a fabricated link. The
consistency checks treat a duplicate ID or a dangling edge as an error, and an
orphan node, an ambiguous alias, or an unresolved reference as a warning. A
`ready_for_submission` true flag, a `HUMAN_REVIEWED` token, or forbidden finality
wording anywhere in the graph is a safety error. Graph consistency does not prove
safety, and a graph warning does not prove a vulnerability.

## 9. Local Validation Coverage Correlation

The coverage correlator connects explicitly linked local-validation result IDs
and trace-receipt IDs to protocol-graph test gaps (and, through them, to function
roles, value paths, and assumptions) as supporting context only. `COVERAGE_TESTED`
means a local-validation result ID was explicitly linked; `COVERAGE_TRACE_BOUND`
means a trace-receipt ID was explicitly linked. Correlation is exact-ID /
explicit-alias only and invents no coverage, no local-validation ID, and no
trace-receipt ID. Tested does not mean safe; trace-bound does not mean proven;
and missing coverage does not prove a vulnerability.

## 10. Evidence and Report Protocol Graph Context

Evidence packages and report drafts can carry an optional `protocol_graph_context`
block summarizing the graph and coverage (counts and linked IDs) as additional
supporting context. The block is additive and optional: a missing block is not an
error, evidence readiness is unchanged, and the trace-bounded `EVIDENCE_READY`
rule is preserved (a tested-only graph context does not create it). The block
keeps `manual_review_required` true and `ready_for_submission` false, never emits
a `HUMAN_REVIEWED` status, and the report stays a draft requiring manual review.

## 11. Review Package Protocol Graph Artifacts

When optional protocol-graph artifacts already exist under
`.arkheionx/out/protocol-graph/` (`graph.json`, `nodes/*.json`, `edges/*.json`,
`checks/*.json`, `coverage-summary.json`, `artifacts-index.json`, and
`checksums/SHA256SUMS`), the review package discovers, classifies, validates,
cross-references, and exports them. They map to seven optional manifest kinds
(`protocol_graph`, `protocol_graph_node`, `protocol_graph_edge`,
`protocol_graph_check`, `protocol_graph_coverage_summary`,
`protocol_graph_artifacts_index`, `protocol_graph_checksums`) and are **never
required**: a missing `protocol-graph/` folder is not an error, and the required
kinds (`review_map`, `evidence_links`, `artifacts_index`) are unchanged.
Validation enforces JSON parseability, path safety, checksum integrity, and the
no-overclaim boundary; cross-references resolve by exact ID / explicit alias only,
and an unresolved reference is a warning. The deterministic ZIP export includes
the graph artifacts with relative-only entries and a stable checksum.

## 16. Known Limitations

- The Protocol Intelligence Core is internal infrastructure: it adds no public
  CLI command, no graph CLI, and no protocol-graph writer. There is no public
  command to generate `.arkheionx/out/protocol-graph/` artifacts in v3.8; the
  review package only packages graph artifacts that already exist.
- It is not a formal audit, not an AI auditor, and not a replacement for a human
  auditor.
- Graph consistency does not prove safety; a graph warning does not prove a
  vulnerability; a passing local test does not prove safety; and a missing test
  does not prove a vulnerability.
- No bounty eligibility and no auto-submit; manual review is always required.
- v3.8.0 is finalized locally: metadata is bumped to `3.8.0` and a local
  annotated `v3.8.0` tag is created; it is not pushed or published, and there is
  no GitHub Release and no post-release cleanup.
