## 2. Summary

v3.7.0 introduces the **Local Validation Integration and Execution Evidence
Layer**: a local-first way to ingest a **saved** Foundry test output file and
turn it into structured, deterministic local-validation artifacts that connect to
the existing Arkheionx evidence graph. Foundry proves local execution; Arkheionx
structures, validates, links, and packages the evidence; the human reviewer
decides.

The new `arkheionx local-validate <repo> --input PATH` command reads **saved
Foundry output only** — it has no live forge runner, requires no Foundry runtime,
and has no subprocess runner. It parses structured or text output, builds
deterministic run / test-result / optional trace-receipt / summary records, links
them to the Protocol Intelligence Model by exact match only, and writes local
artifacts under `.arkheionx/out/local-validation/`. The review package can
include those artifacts (optional, never required), and evidence packages and
report drafts can reference them as supporting context. A passing local test is
supporting context only; a failing local test needs manual review; nothing here
is a confirmed vulnerability or a final severity.

## 4. Local Validation Saved-Output Ingestion

`arkheionx local-validate <repo> --input PATH` ingests a **saved Foundry output
only**. Producing the Foundry output (for example by running `forge test --json`)
is **external** to Arkheionx; the command reads the file you provide and never
runs the tool itself.

- It has no live forge runner and no subprocess runner.
- It has no Foundry runtime requirement: saved-output ingestion works without
  Foundry installed.
- It uses no RPC, no fork-url behavior, and no live-chain calls.
- It reads no private keys and no seed phrases, and it performs no transaction
  broadcasting.
- The optional `--command` string is recorded for provenance only and is never
  executed (no exploit automation, no auto-submit, no command-injection surface).

## 5. Internal Local Validation Model / IDs

`arkheionx/local_validation/model.py` defines the five local-validation
dataclasses (run, test result, trace receipt, artifact, summary), the status and
support vocabularies, and the safety boundary, with a plain `to_dict` serializer.
`arkheionx/local_validation/ids.py` mints deterministic IDs as a short SHA-256
digest over canonical JSON (sorted keys, compact separators) with a
human-readable prefix:

```text
local-validation-run:<tool>:<repo_hash>:<short>
local-test-result:<tool>:<test_hash>:<short>
local-trace-receipt:<tool>:<short>
local-validation-artifact:<kind>:<path_hash>
local-validation-summary:<tool>:<repo_hash>:<short>
```

There is no timestamp as an ID source, no randomness, and no process `hash()`.
Repo paths are normalized to repo-relative POSIX before hashing, and summary IDs
sort their seed inputs so artifact order does not change the ID. The model never
emits an automatic HUMAN_REVIEWED status; it keeps the support vocabulary
(`SUPPORT_TESTED` / `SUPPORT_TRACE_BOUND` / manual-review context) separate from
the existing evidence ladder.

## 6. Foundry Output Parser

`arkheionx/local_validation/parser.py` reads saved output structured-first with a
conservative text fallback. It prefers a saved `forge test --json` document and
parses per-test rows (name, contract, status, and gas/duration when present); it
falls back to a line-based text parse that recognizes `[PASS]` / `[FAIL]` /
`[SKIP]` / `[ERROR]` markers and the suite line. An unrecognized structure or
marker becomes a warning, never a fabricated result. The parser never calls
`forge`, runs no subprocess, requires no Foundry install, and maps a failing test
to a failed status only — never to a confirmed vulnerability, and a passing test
never to an audit-passed or safe outcome. Parsed rows keep their support signal
neutral until the builder runs.

## 7. Local Validation Builder

`arkheionx/local_validation/builder.py` is a pure transform from parsed output to
a `LocalValidationBuildResult` (run, test results, optional trace receipts,
summary). It mints deterministic IDs, derives the summary status conservatively
from the test counts, and links each result to the Protocol Intelligence Model by
exact match only — exact function signature, exact selector, exact contract plus
function, or an explicit alias already on the model. An unresolved test is a
warning with empty link lists, and an ambiguous match is dropped with a warning;
there is no fuzzy or substring matching and no invented link. A passing test
maps to `SUPPORT_TESTED`; failing, skipped, and errored tests stay neutral and
need manual review. The parsed input and the protocol model are never mutated.

## 8. Local Validation Writer

`arkheionx/local_validation/writer.py` writes the build result to
`.arkheionx/out/local-validation/` deterministically:

```text
.arkheionx/out/local-validation/
  summary.json
  run.json
  results/<test_result_id>.json
  traces/<trace_receipt_id>.json     (only when trace metadata is present)
  artifacts-index.json
  checksums/SHA256SUMS
```

JSON is dumped with sorted keys and stable ordering, so repeating a write over
the same input yields byte-identical files and an identical checksum map. The
writer stays inside the repo output root (no traversal, no repo escape), records
repo-relative POSIX paths only (no absolute path, no backslash), excludes the
`SHA256SUMS` file from its own listing, and hard-fails before writing if generated
text would contain `ready_for_submission: true` or an automatic HUMAN_REVIEWED
status.

## 9. local-validate CLI

`arkheionx local-validate <repo> --input PATH` resolves and validates the repo
and the saved input file, parses by `--format auto|foundry-json|foundry-text`,
builds, and (unless `--no-write`) writes the artifacts. Flags: `--json` (one pure
JSON object only), `--no-write` (parse and build in memory; write nothing),
`--output PATH` (must resolve inside the repo), `--tool foundry`, and `--command`
(recorded for provenance only, never executed). Exit codes are `0` success, `2`
invalid repo / input / format / output, and `1` an unexpected build/write error,
with clean one-line errors and no traceback. The JSON object reports the command,
paths (repo-relative), the test counts, `validation_status`, the IDs, the artifact
counts, `manual_review_required` (true), `ready_for_submission` (false),
`warnings`, and `errors`. There is no `--run`, no `--forge`, and no fork/RPC flag.

## 10. Review Package Integration

`arkheionx review-package` discovers the local-validation artifacts automatically
when present and classifies them into optional kinds (`local_validation_summary`,
`local_validation_run`, `local_test_result`, `local_trace_receipt`,
`local_validation_artifacts_index`, `local_validation_checksums`). They are
optional and never required: a missing `local-validation/` folder yields no
artifacts and no error, and the required kinds (`review_map`, `evidence_links`,
`artifacts_index`) are unchanged. Validation checks the local-validation JSON
parses, the `SHA256SUMS` digests match, paths are safe, and there is no overclaim;
a forbidden positive marker (an automatic HUMAN_REVIEWED, a `ready_for_submission:
true`, an audit-passed, a confirmed-vulnerability, a final-severity, or a
guaranteed-bounty form) is a safety failure that blocks export. Cross-reference
resolution is exact ID or explicit alias only. The deterministic ZIP export
includes the copied local-validation artifacts with relative-only entries and a
stable archive checksum.

## 11. Evidence and Report Support Context

Evidence packages and report drafts can reference local-validation
tested / trace-bound signals as **supporting context only**. The evidence payload
gains an optional `local_validation_support` block and the report draft gains an
optional "Local Validation Context" summary; both are omitted when no
local-validation artifacts exist. A passing local test is `SUPPORT_TESTED`
context; a passing local test with an explicit linked local trace receipt is
`SUPPORT_TRACE_BOUND` context; failing, skipped, and errored local tests are
manual-review context, never a confirmed vulnerability.

The evidence readiness ladder is unchanged: `EVIDENCE_READY` still requires an
execution-confirmed proof plus a linked trace artifact, and a tested-only local
signal does not create it. No local-validation signal raises the evidence level
by itself, assigns a final severity, marks an audit passed, claims bounty
eligibility, emits an automatic HUMAN_REVIEWED status, or sets
`ready_for_submission` true. The report stays a draft requiring manual review.

## 13. Safety Boundaries

Arkheionx remains local/static review guidance only. Every local-validation
output declares, all true:

- local/static only
- saved Foundry output only (no live forge runner, no subprocess runner)
- no Foundry runtime requirement
- no RPC
- no fork-url
- no private keys
- no seed phrases
- no live-chain calls
- no transaction broadcasting
- no exploit automation
- no auto-submit
- no automatic `HUMAN_REVIEWED`
- no confirmed vulnerabilities
- no final severity
- no audit-passed claim
- no bounty eligibility
- manual review required
- `ready_for_submission` false

Local validation structures local execution evidence for review. It does not turn
a passing or failing local test into vulnerability confirmation, exploitability
proof, final severity, or submission readiness. It is not a formal audit, not an
AI auditor, and not a replacement for a human auditor.

## 16. Known Limitations

- Saved-output ingestion only: Arkheionx reads a saved Foundry output file and
  never runs `forge`; producing that file is external to Arkheionx.
- Not a formal audit, not an AI auditor, and not a replacement for a human
  auditor.
- A passing local test is supporting context only and never proves absence of
  bugs; a failing local test needs manual review and is not a confirmed
  vulnerability or a final severity.

- Local validation never raises the evidence ladder by itself; the trace-bounded
