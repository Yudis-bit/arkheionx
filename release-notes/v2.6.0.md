# Arkheionx v2.6.0 — arkup & Version-Manager MVP

Arkheionx v2.6.0 turns the v2.5.0 installer into a clean, honest install/update
lifecycle: **install → check → update → inspect → uninstall**. The core
evidence workflow is unchanged.

> Release date: 2026-05-31. Package version `2.6.0`. The `STABLE_RELEASE`
> pointer remains `v2.5.0` until this release is published, then moves to
> `v2.6.0` in post-release cleanup. Not published to PyPI. Not a formal audit;
> no bounty or severity guarantee.

## Summary

A small `arkup` helper, a local install receipt, and an explicit
stable/main/ref/local source model make Arkheionx feel like a serious developer
tool while staying local-first: no root, no shell-profile edits, no secrets, no
RPC.

## Highlights

- `arkup` — MVP install/update lifecycle helper (not a full version manager).
- Install receipt (`~/.arkheionx/install.json`) describing how Arkheionx was installed.
- Source model: `stable` / `main` / `ref` / `local` with predictable updates.
- `arkheionx doctor --install` now reports the receipt, consistent with `arkup --check`.

## What changed since v2.5.0

- Added the root-level `arkup` script and `schemas/install-receipt.schema.json`.
- `install.sh` now resolves a source model and writes the install receipt.
- `uninstall.sh` shows and removes the receipt (path guard unchanged).
- `doctor --install` gained an install-receipt section.
- Version metadata finalized to `2.6.0`.

## arkup

```sh
sh arkup --help
sh arkup --version
sh arkup --check          # alias: --status
sh arkup --install [--channel stable|main] [--ref REF] [--local PATH]
sh arkup --update         # keeps the recorded source kind
sh arkup --uninstall [--dry-run]
```

`arkup` is an MVP wrapper around `install.sh`/`uninstall.sh` and the install
receipt. It does not claim parity with foundryup, edits no shell profile, and
uses no root.

## Install receipt / install state

`install.sh` writes `$ARKHEIONX_INSTALL_DIR/install.json` on success: schema
version, timestamps, install method, source kind, repo/ref/local path, install
and bin dirs, command path, detected Python, and installed version. It is local
runtime state, never committed, and removed by `uninstall.sh`. Schema:
`schemas/install-receipt.schema.json`.

## Update flow

`arkup --update` reads `source_kind` and preserves it: `stable` reinstalls the
stable tag, `main` reinstalls main, `ref` stays pinned, `local` reinstalls from
the same path. It never silently changes channel/ref; pass an explicit
`--channel`/`--ref`/`--local` to override. See `docs/UPDATE_FLOW.md`.

## Doctor / status improvements

`arkheionx doctor --install` reports command path, Python, package version,
optional Foundry status, PATH reachability, and the install receipt. It agrees
with `arkup --check`. Default `arkheionx doctor` output is unchanged.

## Safety boundaries

- Local/static only; no RPC by default; no live-chain mutation.
- No root, no shell-profile edits, no secrets, no private keys.
- No PyPI, Homebrew, standalone binaries, or domain installer.
- No background or automatic updates; no telemetry.

## Known limitations

- `arkup` is an MVP wrapper, not a full version manager.
- No PyPI, Homebrew, binary, or domain-installer distribution.
- Updates pull from git/local only; no background updates.
