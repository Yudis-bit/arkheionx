# 30-Day Growth Sprint

This sprint is designed to create qualified conversations quickly without
turning the archive into generic hype. Run it once, measure honestly, then
repeat the best-performing channel.

## North Star

Book paid discovery conversations for:

- assertion hardening sprints,
- auditor workshops,
- historical exploit reports,
- sponsorship conversations.

## Targets

| Metric | 30-day target |
|---|---:|
| Qualified accounts researched | 200 |
| Personalized outbound messages | 80 |
| Warm intro requests | 40 |
| Technical posts | 20 |
| Longer writeups | 4 |
| Community or partner asks | 20 |
| Discovery calls booked | 8 |
| Proposals sent | 4 |
| Paid engagements closed | 1-2 |
| Sponsors or recurring supporters | 3-5 |

## Week 1: Setup and Proof

Goal: make the public surface easy to understand and easy to buy.

- Confirm the GitHub Sponsor button works from `.github/FUNDING.yml`.
- Add repository topics in GitHub settings:
  `defi`, `smart-contract-security`, `foundry`, `exploit-analysis`,
  `security-research`, `web3-security`, `poc`.
- Pin the repository on the GitHub profile.
- Add the service menu to all profile bios and social profiles.
- Publish the commercial launch post from `docs/launch/COMMERCIAL_LAUNCH_POSTS.md`.
- Publish one technical post explaining why logs are not proof.
- Build the first 50 target accounts.
- Send 20 personalized messages.

## Week 2: Content and Conversations

Goal: use technical content to create buyer conversations.

- Publish 5 short posts from `docs/marketing/CONTENT_PLAYBOOK.md`.
- Publish one deeper writeup: "How to turn a weak exploit replay into hard
  assertions."
- Send 20 personalized messages.
- Ask 10 warm contacts for intros to security educators, audit leads, or
  protocol security teams.
- Pitch 5 community organizers for a workshop.
- Offer 2 pilot workshop slots with fixed dates.

## Week 3: Partner Push

Goal: borrow trust from communities and existing security audiences.

- Pitch 10 communities, bootcamps, newsletters, or small audit teams.
- Offer one guest session:
  "Exploit Anatomy for Auditors: Assertion-Driven PoCs."
- Turn one repo entry into a short case-study sample.
- Send 20 personalized messages.
- Follow up with leads from weeks 1 and 2.
- Send proposals to qualified buyers who confirmed scope.

## Week 4: Conversion

Goal: close one small paid offer and one recurring support path.

- Repost the best-performing technical lesson with a direct service CTA.
- Publish a sponsor progress note:
  current weak entries, current L4 count, next funded work.
- Send 20 personalized messages.
- Close one Assertion Hardening Sprint or workshop.
- Ask every positive reply:
  "Who else should see this?"
- Update the KPI tracker and choose next month's focus.

## Daily Block

Run this in 90 minutes:

1. 20 minutes: write or repurpose one technical post.
2. 30 minutes: personalize and send 5 outbound messages.
3. 20 minutes: reply and follow up.
4. 10 minutes: log metrics.
5. 10 minutes: improve one public asset.

## Offer Rotation

Do not sell everything at once. Rotate the CTA:

| Week | Primary CTA |
|---|---|
| 1 | Sponsor the public archive |
| 2 | Book an auditor workshop |
| 3 | Request an assertion hardening sprint |
| 4 | Ask for a historical exploit report |

## Friday Review

Answer these every Friday:

- Which post generated replies from actual buyers?
- Which target segment replied fastest?
- Which CTA produced calls, not just likes?
- Which objections repeated?
- Which offer should be removed, renamed, or repriced?
- What proof should be added to the repo next?

## Minimum Viable Paid Goal

The first closed deal should be narrow:

```text
Assertion Hardening Sprint
Scope: one existing Foundry PoC
Output: assertions, invariant map, reviewer memo, metadata notes
Price: USD 750-2,500 depending on complexity
Timeline: 3-7 business days
```

Small paid proof is more useful than a large unfocused pipeline.
