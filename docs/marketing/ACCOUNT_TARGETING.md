# Account Targeting

Use this to build a qualified target list. The purpose is not bulk scraping or
spam. Each account should have a clear reason to care about historical exploit
analysis, assertion quality, or security education.

## Best-Fit Segments

| Segment | Buyer | Pain | Offer |
|---|---|---|---|
| Small audit teams | Founder, audit lead | Junior reviewers need better exploit-reading practice | Workshop |
| Protocol security teams | Security lead, engineering manager | Internal incident education is scattered | Historical report |
| Web3 bootcamps | Curriculum lead | Need realistic defensive case studies | Workshop |
| Security communities | Organizer | Need technical guest sessions | Sponsored workshop |
| Independent researchers | Maintainer, reviewer | PoCs are hard to verify and explain | Assertion sprint |
| DAOs with security budgets | Security working group | Need public-good proof for funding | Sponsorship |
| Incident post-mortem writers | Research lead | Need precise root-cause framing | Report review |

## Qualification Fields

Track each lead in a private spreadsheet or CRM:

| Field | Example |
|---|---|
| Account | Small audit team name |
| Segment | Audit team |
| Contact | Audit lead |
| Channel | LinkedIn / X / email / intro |
| Why relevant | Publishes exploit writeups |
| Likely offer | Workshop |
| Personalization point | Their recent post on PoC quality |
| Scope safety | Historical / education / authorized |
| Status | Not contacted / sent / replied / call / proposal / closed |
| Next action | Follow up on Tuesday |

Do not store private keys, confidential exploit details, private RPC URLs, or
undisclosed vulnerability material in the tracker.

## Lead Scoring

Score each account from 0 to 10:

| Signal | Points |
|---|---:|
| Has security education or research budget | 2 |
| Publishes technical security content | 2 |
| Works with DeFi or EVM systems | 2 |
| Has a clear training or PoC quality need | 2 |
| Warm intro available | 1 |
| Public contact path exists | 1 |

Only send outbound to accounts scoring 6 or higher.

## High-Intent Triggers

Prioritize leads when they:

- publish an exploit post-mortem;
- announce security training or a research cohort;
- hire smart contract auditors;
- discuss Foundry, fork testing, or PoC reproducibility;
- run a security community event;
- maintain public incident databases;
- ask for educational security material.

## Personalization Angles

Use one precise angle per message:

- "Your team publishes exploit notes; this turns them into assertion exercises."
- "Your juniors need repeatable exploit-reading drills."
- "Your community discusses DeFi incidents; this can be a structured session."
- "Your internal PoCs may be useful but hard to review without assertions."
- "Your sponsor budget can fund public verification work with visible progress."

## Who Not To Contact

Avoid:

- teams in an active incident;
- accounts requesting live exploitation;
- people asking for private exploit adaptation;
- projects with no public technical context;
- buyers who only want a bounty outcome;
- communities that prohibit commercial outreach.

## Weekly Target Mix

For each batch of 50 accounts:

| Segment | Count |
|---|---:|
| Audit teams | 15 |
| Protocol security teams | 10 |
| Security communities | 10 |
| Bootcamps / education | 5 |
| Independent researchers | 5 |
| DAO/security public-goods funders | 5 |

This keeps the pipeline balanced between services, training, and sponsorship.
