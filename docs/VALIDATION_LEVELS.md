# Validation Levels

Arkheionx separates internal demos from external validation so public language
stays honest.

## Levels

| Level | Meaning | Allowed Claim |
|---|---|---|
| Level 0 | Internal toy/demo only | Internal demo fixture validated. |
| Level 1 | Public user tried the demo | Public demo feedback received. |
| Level 2 | Public user ran Arkheionx on a toy/public repo | Public evaluation on toy/public repo. |
| Level 3 | Authorized private repo feedback, anonymized | Anonymized authorized feedback received. |
| Level 4 | Public case study with permission | Public case study available. |
| Level 5 | Multiple public independent evaluations | Multiple independent public evaluations documented. |

## Current Status

Current public materials include internal demo fixtures, self-simulation, and
feedback workflows. v1.1.0 adds the process for external calibration.

Do not claim broad adoption, customer use, production trust, or auditor
endorsement unless committed public evidence exists.

## Allowed Language

- Feedback workflow available.
- Internal demo fixture validated.
- External feedback welcome.
- Public case study available when permission and evidence are committed.

## Disallowed Language Without Evidence

- Used by top protocols.
- Trusted by auditors.
- Proven in production.
- Adopted by teams.
- Guaranteed to find bugs.
- Replacement for a formal audit.

## Why This Matters

Arkheionx is a pre-audit readiness system. Historical pattern similarity and
readiness findings are useful context, not proof that a repository has or does
not have a vulnerability.
