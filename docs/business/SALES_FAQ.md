# Sales FAQ

## Is Arkheionx a formal audit?

No. Paid Arkheionx work is a readiness engagement, not a formal audit.

## What does a buyer receive?

Depending on scope, buyers receive generated readiness artifacts plus manual
review, prioritization, issue-plan cleanup, and a walkthrough.

## What is the difference from an audit?

Arkheionx focuses on pre-audit readiness: missing invariants, documentation
gaps, issue planning, scope clarity, rule calibration, and defensive test
planning. A formal audit attempts deeper expert review and should still be
performed before material user funds are at risk.

## Does Arkheionx guarantee security or bounty findings?

No. Arkheionx does not guarantee security, bounty outcomes, exploit discovery,
or vulnerability confirmation.

## Can private repositories be reviewed?

Only if the requester owns or is authorized to submit the repository. Private
code should be shared through an agreed private channel, never a public issue.

## What should not be sent?

Do not send private keys, mnemonics, RPC secrets, API tokens, customer data, or
unpatched vulnerability details in public channels.

## Does Arkheionx use live-chain scanning?

No. The default workflow is local/static repository analysis. Paid work does
not add RPC calls, transaction execution, deployed-contract scanning, or exploit
automation.

## What does a pilot look like?

A pilot has a narrow scope, a short timeline, and concrete deliverables. For
example: one Readiness Snapshot, one Pre-Audit Sprint, or a small Ecosystem
Readiness Pilot across 3-5 authorized repositories.

## Can Arkheionx mention the buyer publicly?

Only with explicit public permission. No adoption, customer, or partnership
claim should be made without committed evidence and consent.
