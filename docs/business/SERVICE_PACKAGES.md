# Service Packages

This page explains what a buyer receives from each Arkheionx paid readiness
offer.

Paid Arkheionx work is a readiness engagement, not a formal audit.

## Arkheionx Readiness Snapshot

Purpose:

- quick pre-audit repository readiness scan;
- identify obvious audit blockers;
- generate a report and issue plan.

Deliverables:

- Pre-Audit Readiness Report;
- Executive Summary;
- Issue Plan;
- top 5-10 readiness gaps;
- 30-minute walkthrough.

Not included:

- formal audit;
- exploit PoC development;
- live-chain testing;
- unlimited remediation support.

## Arkheionx Pre-Audit Sprint

Purpose:

- 3-5 day guided readiness workflow before audit, contest, or bug bounty launch;
- turn readiness findings into a prioritized remediation roadmap.

Deliverables:

- Pre-Audit Report;
- SARIF;
- GitHub Issue Plan;
- Remediation Roadmap;
- Contest Readiness Report;
- suggested invariant/test plan;
- 60-90 minute walkthrough;
- optional follow-up calibration pass.

Not included:

- formal audit sign-off;
- security guarantee;
- exploit development;
- emergency incident response.

## Contest Readiness Pack

Purpose:

- make the repository easier for authorized researchers to review;
- improve scope clarity and onboarding before external review.

Deliverables:

- contest readiness checklist;
- scope clarity review;
- documentation gap review;
- issue plan;
- researcher onboarding notes;
- common audit-blocker list.

No endorsement, certification, or affiliation with any named contest platform is
implied.

## GitHub Action Setup

Purpose:

- help a team add Arkheionx to GitHub Actions safely;
- produce repeatable readiness artifacts in CI.

Deliverables:

- GitHub Action integration;
- SARIF output;
- report artifact setup;
- config/suppression setup;
- recommended thresholds;
- short handoff guide.

Issue creation remains disabled unless explicitly scoped and token-controlled
by the repository owner.

## Ecosystem Readiness Pilot

Purpose:

- support ecosystem-level readiness across multiple authorized repositories;
- identify common readiness gaps without naming teams publicly unless
  permission exists;
- give operators a repo-by-repo table, anonymized common-gap summary, and
  rule-family heatmap.

Deliverables:

- Ecosystem Readiness Summary;
- Repo-by-Repo Readiness Table;
- Common Gap Report;
- Rule-Family Heatmap;
- Anonymized Recommendations;
- GitHub Action Setup Recommendations;
- Feedback and Calibration Notes;
- 60-90 minute ecosystem walkthrough.

Suggested scope:

- pilot: 3-5 authorized repositories;
- expanded: 5-10 authorized repositories.

Not included:

- formal audit;
- vulnerability certification;
- exploit development;
- live-chain testing;
- emergency incident response;
- public claims without permission;
- reviewing unauthorized repositories.
