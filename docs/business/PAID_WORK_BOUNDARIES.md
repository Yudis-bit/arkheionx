# Paid Work Boundaries

Arkheionx commercial work must strengthen public trust, not spend it.

Paid Arkheionx work is a readiness engagement, not a formal audit.

## Allowed

- Pre-audit readiness review.
- Audit preparation.
- Contest preparation for authorized maintainers.
- Report quality review.
- Issue planning.
- Remediation roadmap planning.
- Rule calibration feedback.
- GitHub Action setup for authorized repositories.
- Ecosystem readiness summaries for multiple authorized repositories.
- Anonymized common-gap reports.
- Local/static analysis.

## Not Allowed

- RPC calls or live-chain scanning.
- Deployed-contract attack analysis.
- Transaction execution.
- Exploit payload generation.
- Target enumeration.
- Drain simulation.
- Private key, mnemonic, API token, or secret handling.
- Unauthorized repository scanning.
- Public naming of participating repos without permission.
- Public ecosystem or partner claims without committed evidence and consent.
- Attack automation or evasion tooling.
- Bounty farming automation.
- Payment processing, CRM, or email automation in this repository.

## Claim Boundaries

Do not claim:

- formal audit coverage;
- security guarantees;
- bug bounty guarantees;
- exploit discovery guarantees;
- official certification;
- customer adoption;
- auditor trust;
- partnerships with audit firms, contest platforms, or bounty platforms.

Use:

- readiness support;
- readiness signal;
- review recommended;
- issue planning;
- defensive review;
- authorized repository;
- local/static analysis;
- human-guided readiness review.

## Disclosure Boundaries

If a paid engagement surfaces potential unpatched vulnerability information:

1. Pause public discussion.
2. Move to the agreed private disclosure path.
3. Avoid exploit steps in public artifacts.
4. Follow the relevant protocol, bounty, or platform disclosure policy.
