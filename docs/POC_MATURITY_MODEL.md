# PoC Maturity Model

This document defines the maturity ladder Arkheionx Vault uses to grade
each PoC honestly. It complements [`POC_STANDARD.md`](POC_STANDARD.md),
[`ASSERTION_STANDARD.md`](ASSERTION_STANDARD.md), and
[`REPRODUCIBILITY_STANDARD.md`](REPRODUCIBILITY_STANDARD.md).

The model exists so the public registry, the README, and the per-PoC
verification reports can describe each entry's readiness without
overclaiming. A PoC that compiles is not a PoC that proves anything; a
PoC that runs against a public RPC is not a PoC that runs against the
historical block of the incident.

The maturity index lives at
[`reports/poc_maturity_index.md`](../reports/poc_maturity_index.md) and
is generated by [`scripts/poc_maturity_index.py`](../scripts/poc_maturity_index.py).

---

## Levels

### L0 — Raw Replay

The PoC compiles or replays the shape of the exploit, but the proof is
weak.

**Requirements**

- Foundry test exists at the path declared in `metadata.poc_path`.
- File compiles under `forge build` from `EVM/`.
- A registry entry exists with at least `id`, `title`, `protocol`,
  `chain`, `vm`, `poc_path`, and a placeholder reproducibility status.

**Evidence**

- Source file present.
- Registry entry validates against `metadata/schema.json`.

**What does not count**

- A PoC with `console.log(attackerBalance)` and no `assert*` calls.
- A PoC whose category is `unknown` or whose root cause is empty.

**Promotion to L1** — fill structured metadata: `category`,
`root_cause`, `invariant_broken`, `protocol_assumption_failure`,
`attacker_path`, references.

---

### L1 — Structured Metadata

The PoC has a complete, honest registry entry. Anyone reading the
metadata can understand the failure mode without reading the source.

**Requirements**

- All L0 requirements.
- Required metadata fields populated. No `unknown` placeholders for
  fields the [`METADATA_SCHEMA`](METADATA_SCHEMA.md) marks required.
- `category` matches one of the [`EXPLOIT_TAXONOMY`](EXPLOIT_TAXONOMY.md)
  values.
- `root_cause`, `invariant_broken`, `protocol_assumption_failure`, and
  `attacker_path` are substantive, not placeholders.
- At least one external `references` entry (post-mortem, advisory, or
  authoritative writeup).
- For `historical` entries: `block_number` and `attack_tx` populated
  unless explicitly justified in `notes`.

**Evidence**

- `python3 scripts/validate_metadata.py` passes.
- `score_pocs.py` reports metadata completeness `20 / 20`.

**What does not count**

- An entry that lists generic references with no link to the original
  incident.
- An entry whose `summary` is one sentence and whose `root_cause` is
  blank.

**Promotion to L2** — add the assertion families required by the
category in
[`ASSERTION_STANDARD.md`](ASSERTION_STANDARD.md).

---

### L2 — Assertion-Hardened

The PoC includes hard assertions that prove the compromise. A green test
is no longer trivially green.

**Requirements**

- All L1 requirements.
- `assertion_quality` is `medium` or `strong` per
  [`ASSERTION_STANDARD.md`](ASSERTION_STANDARD.md).
- At least one of:
  - attacker profit assertion against pinned pre-state,
  - victim loss / state-damage assertion,
  - invariant break assertion (F1–F9 family per category).
- For `strong`: the required family set for the category is fully
  covered.

**Evidence**

- `assert*` calls present in the test file matching the assertion
  contract documented in the registry entry.
- Static review note in `metadata.notes` if the family coverage is
  partial (justifies a `medium` rating).

**What does not count**

- A `console.log` with a number that "looks right".
- An assertion against a value the PoC itself just wrote in `setUp()`.

**Promotion to L3** — attempt the PoC on a public RPC at the declared
`block_number` and record the outcome in
`metadata.latest_public_rpc_status`.

---

### L3 — Public RPC Smoke-Tested

The PoC has been attempted on a public RPC. The outcome is recorded —
pass, fail, or "public RPC lacks archive state at this block" — without
upgrading the verification claim.

**Requirements**

- All L2 requirements.
- `metadata.latest_public_rpc_status` is one of the documented values:
  - `public-rpc-pass` — `setUp()` and exploit body executed without
    revert against a public RPC.
  - `public-rpc-not-archival` — public RPC rejected the fork at the
    declared block (historical state pruned). This is **not** a PoC
    failure; it is an RPC limitation. See
    [`FORK_VERIFICATION.md`](FORK_VERIFICATION.md).
  - `public-rpc-fail` — public RPC accepted the fork and the test
    failed. This must be triaged before claiming any further maturity.

**Evidence**

- A `notes` entry referencing the smoke-test phase report (e.g. Phase
  4A) or a recorded run.
- Optional: a verification stub under `reports/verification/` noting
  the smoke result without claiming verification.

**What does not count**

- "It compiled, so it works."
- A pass on a non-archival RPC at a recent block when the metadata
  declares a historical block — the fork did not actually use the
  declared block.

**Promotion to L4** — re-run on archival RPC at the declared
`block_number`, capture full output, and write a verification report.

---

### L4 — Archival Verified

The PoC has been re-run against an archival RPC at the pinned
`block_number`, the declared assertions passed, and a verification
report has been written.

**Requirements**

- All L3 requirements.
- `metadata.reproducibility` is `deterministic-confirmed`.
- `metadata.verification_status` is `verified`.
- A complete verification report exists at
  `reports/verification/<id>.md` with the run transcript, archival RPC
  alias, fork block, commit SHA, and verifier handle filled in (not
  placeholder values).
- `assertion_quality` is at least `medium`. A `weak` PoC cannot be
  L4 — without strong assertions there is nothing meaningful for an
  archival run to prove.

**Evidence**

- Run transcript in the verification report.
- Same fork block in the test source and the metadata entry.
- The verification report's commit SHA matches a commit on this
  branch's history.

**What does not count**

- A green `forge test` against an archival RPC where the assertions
  are `console.log` calls — that is L3 with archival flavor, not L4.
- A run on an RPC that silently fell back to the latest block.
- A run whose report has not been committed.

**Promotion to L5** — add the case-study artifacts: root-cause
write-up, patch lesson, auditor checklist exercise.

---

### L5 — Research-Grade Case Study

The PoC is a published case study: verified at L4, with a long-form
root-cause write-up, a patch lesson, and a worked auditor checklist.

**Requirements**

- All L4 requirements.
- A `WRITEUP.md` in the same directory as the PoC, or a
  `docs/case-studies/<id>.md`, covering:
  - exploit primitive in depth,
  - the broken invariant explained against the contract code,
  - the patch (or patches) the protocol shipped,
  - what an auditor reviewing similar code should look for next time.
- An [`AUDITOR_CHECKLIST`](AUDITOR_CHECKLIST.md) walkthrough applied to
  this PoC, with the relevant prompts answered.
- An entry in the [`ROOT_CAUSE_PLAYBOOK`](ROOT_CAUSE_PLAYBOOK.md) that
  references this PoC as a worked example (or this PoC referenced from
  the playbook section that already exists).

**Evidence**

- All of the above committed and linked from the registry entry's
  `notes` field or a `case_study` reference.

**What does not count**

- A blog post that summarises the post-mortem without engaging with the
  contract code.
- A case study without a corresponding L4 verification.

---

## Demotion rules

A PoC may be demoted in these cases:

- **L4 → L3** if the archival RPC drifts (provider deprecates the
  block) and the run can no longer be reproduced on this branch.
- **L3 → L2** if the metadata `block_number` is changed without
  re-running the smoke test.
- **L2 → L1** if a refactor weakens the assertions and `assertion_quality`
  drops to `weak` or `none`.

Demotions must be reflected in metadata in the same change. Hidden
demotions (a stronger label sticking around after the underlying
evidence is gone) are not allowed.

## Current corpus snapshot

The maturity index regenerates from `metadata/registry.json` on demand:

```sh
python3 scripts/poc_maturity_index.py
python3 scripts/poc_maturity_index.py --check
```

The current corpus has **18 PoCs**, **0** at L4, **0** at L5. The
distribution sits between L1 and L3, with assertion-hardened entries
ready for archival verification once an archival RPC is configured. See
[`reports/poc_maturity_index.md`](../reports/poc_maturity_index.md) for
the per-entry breakdown.
